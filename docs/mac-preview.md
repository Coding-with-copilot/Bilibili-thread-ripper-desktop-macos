# Mac 预览版使用说明

本目录的 Mac 移植只接管播放窗口的媒体下载，保留哔哩哔哩原播放器。它没有 BTR 自动更新、手动更新检查或 Windows 维护程序。

## 立即测试

当前已从项目根目录的 `哔哩哔哩.app` 生成诊断版测试副本：`/private/tmp/哔哩哔哩-BTR-diagnostic.app`。原版应用没有被修改。

1. 完全退出正在运行的哔哩哔哩，包括菜单栏或 Dock 中残留的进程。
2. 在终端执行：

   ```sh
   open -n '/private/tmp/哔哩哔哩-BTR-diagnostic.app'
   ```

3. 打开普通视频，检查播放器齿轮菜单中的“线程撕裂者 CDN / 并发线程”。进入客户端设置时，也应能看到“线程撕裂者”设置区。
4. 播放一段视频并拖动进度条。播放器齿轮菜单里的“诊断”一行会显示接管次数、媒体 fetch/XHR 数量、页面资源数量和最近跳过原因。请记录这整行的文字。
5. “已收到客户端播放地址”和“视频数据已交给客户端”属于 Debug 提示，默认隐藏；要看这些提示，在 BTR 设置中打开 Debug 模式。“显示错误”可以另外打开。

测试副本位于临时目录，系统清理临时文件后需要重新生成。它与原版应用使用同一客户端数据目录；测试前先退出原版，避免两个实例同时运行。

## 重新生成

在本机有 Node.js 时，进入 `Bilibili-thread-ripper-desktop-main`，运行：

```sh
node tools/mac-port.cjs install '../哔哩哔哩.app' '/private/tmp/另一个BTR测试.app'
```

输出路径必须尚不存在。也可把输出设在自己的非云同步目录，例如 `~/Applications/哔哩哔哩-BTR.app`。脚本复制原应用、加入 Mac 注入代码、更新 Electron 的 ASAR 完整性哈希，再为本地副本做临时签名；不需要 Apple 开发者证书。BTR 不会检测或安装更新。官方客户端自身升级后，请从新的原版应用重新生成副本。

## 请反馈的结果

- 测试副本能否启动、登录、正常播放；
- 播放器齿轮和客户端设置是否出现 BTR 选项；
- 播放或拖动后，播放器齿轮菜单“诊断”一行的完整文字；
- 如果播放失败，Debug 和“显示错误”出现的原文。

目前完成了封装、完整性和本地签名校验，以及下载逻辑的自动化测试；尚未在真实播放器里实测。因此首次测试的重点是确认 Mac 客户端播放窗口的实际地址和媒体请求能否命中接管规则。
